# tutu-swipe

Свайп-подбор путешествий поверх MCP Туту. Свободная фраза вместо формы, лента готовых поездок вместо выдачи, обучение на реакциях внутри сессии.

**Проект ИИ-хакатона Туту, август 2026.**

---

## Проблема

Тревел-поиск работает, когда человек знает, куда едет. Когда не знает — уходит выбирать в телеграм-каналы, Пинтерест или к друзьям и возвращается уже с названием города. Сервис получает транзакцию и не участвует в самом ценном: в выборе.

Фраза «хочу на море в сентябре, вдвоём из Москвы, тысяч за шестьдесят, чтобы не шумно» не превращается в поисковый запрос ни в одном тревел-сервисе.

## Что делает продукт

1. Разбирает свободную фразу правилами, без обращения к модели на типичном запросе
2. Подбирает 3–8 направлений-кандидатов по каталогу
3. Ищет по каждому дорогу и жильё параллельно, собирает готовые поездки с итоговой ценой
4. Показывает ленту: первая карточка — за **17 миллисекунд**, живые данные догоняют и заменяют её
5. Учится на реакциях: лайки и дизлайки с причинами перестраивают выдачу
6. Объясняет каждую карточку — или молчит, если подтверждений мало
7. Отдаёт подборку ссылкой и ведёт на Туту

## Главный технический тезис

**MCP Туту не умеет discovery.** Все инструменты поиска — `search_avia`, `search_rail`, `search_hotels`, `search_multitransport` — требуют явный `destination`. Запроса «покажи, куда поехать» на уровне API не существует.

Поэтому слой подбора направлений построен на нашей стороне: каталог 56 направлений с типами локаций, сезонностью и досягаемостью, детерминированный отбор кандидатов и веерный поиск по ним. Это и есть основная инженерная работа проекта.

## Как решена скорость

Замер живого MCP: **холодное направление отвечает 10,8 секунды**, прогретое — 0,5–1,5. Никакой оптимизацией кода этот разрыв не закрыть.

Решение — предзаготовленный снапшот: каталог прогоняется заранее, 227 карточек лежат в репозитории и отдаются мгновенно, а живой поиск идёт параллельно и заменяет их. Возраст цены показывается, замена видна — снапшот не выдаётся за актуальные данные.

| Метрика | Значение |
|---|---|
| Первая карточка пользователю | **17 мс** |
| Загрузка снапшота | 2,2 мс (325 КБ, 227 карточек) |
| Полный ответ с живыми данными | 1,4–4,9 с |
| Холодный вызов MCP без снапшота | 10 800 мс |

## Как работает обучение

Байесовская линейная регрессия с диагональной ковариацией на 8–10 плотных признаках. Апостериорное распределение аналитическое, поэтому Thompson sampling корректен: веса сэмплируются из настоящего распределения, а не из точечной оценки с подмешанным шумом. Дисперсии убывают с накоплением реакций — разведка сужается сама.

Дизлайк сопровождается причиной (дорого / долго / не тот город / не тот отель), и причина двигает адресные веса. Два «не тот город» подряд запускают подбор новых направлений.

**Честная оценка эффекта** — в [docs/ranking-baseline.md](docs/ranking-baseline.md): реакции разделены по времени, обучение на первых 70%, измерение на последних 30%, которых модель не видела.

| Режим | Средняя позиция лайкнутых карточек (held-out) |
|---|---|
| Байесовская модель | 37,1 |
| Взвешенные правила | 45,8 |
| Сортировка по цене | 112,3 |
| Случайный порядок | 134,8 |

Отчёт сам называет свои пределы: девять проверочных лайков — малая выборка, преимущество модели над эвристиками не доказано, вывод предварительный.

## Запуск

Нужен Node ≥ 22.

```bash
npm install
cp .env.local.example .env.local   # заполнить SESSION_STATE_SECRET
npm run dev                        # http://localhost:3000
```

### Проверки

```bash
npm run check    # типы, линт, тесты, архитектурные границы, аудит фич
npm run smoke    # сборка, запуск, критические маршруты
npm test         # только тесты
```

### Обновление данных

```bash
node scripts/validate-catalog.mjs    # проверить пригодность направлений через MCP
node scripts/build-snapshot.mjs      # перестроить снапшот (несколько минут)
```

Снапшот стоит перестраивать перед демонстрацией: цены недельной давности выглядят хуже, чем их отсутствие.

### Развёртывание

```bash
docker build -t tutu-swipe:latest .
docker compose -f docker-compose.yml -f docker-compose.production.yml up -d
```

Приложение приватно и выходит наружу только через Traefik. Переменные — в `.env.example`.

## Архитектура коротко

```
Клиент (лента, подборка)
   │
API-маршруты ── сценарии ──┬── discovery  разбор фразы, каталог, отбор
   │                       ├── search     веер, поток, бюджет времени
   │                       ├── packages   сборка поездок, цены
   │                       ├── ranking    признаки, две реализации ранжировщика
   │                       ├── explain    объяснения из журнала реакций
   │                       └── link       кодирование подборки в ссылку
   └── mcp ── MCP Туту
```

Подробнее — [SPEC_PLAN/ARCHITECTURE.md](SPEC_PLAN/ARCHITECTURE.md).

**Внешнего хранилища нет.** Состояние сессии живёт в браузере и приходит подписанным; веса модели не передаются вовсе — сервер пересчитывает их из журнала реакций. Подборка кодируется во фрагмент ссылки, поэтому даты, бюджет и возрасты детей не попадают в серверные логи.

**Границы слоёв проверяются машиной.** `ranking`, `explain` и `packages` не имеют права импортировать `mcp` — правило ловит алиасы, импорт типов и транзитивные реэкспорты, печатая цепочку зависимости.

## Что мы узнали об API Туту

Неочевидное поведение, которое пришлось выяснять замерами — полностью в [docs/surprises.md](docs/surprises.md):

- **Транспорт и отели по-разному сообщают о ненайденном городе.** Транспорт отвечает успехом с причинами в `meta.unavailable`, отели — флагом ошибки и текстом, который не является JSON
- **Достижимость зависит от города отправления.** Белокуриха не резолвится из Москвы, но находится из Новосибирска — проверять направление одним запросом недостаточно
- **Четыре направления не резолвятся вовсе**, включая Суздаль: туда нет железной дороги, а автобусные связки MCP не собирает
- **Поле `also_named` на практике не приходит.** «Гагарин» молча становится Саратовом, «Ростов» — Ростовом-на-Дону
- **`tutu://geo` — не справочник городов**, там всего два города и точки внутри них
- **У сервера есть кэш**: холодный вызов 10,8 с, прогретый 0,5 с

# PRD — tutu-swipe

**Дата:** 2026-08-04 · **Режим:** lite
**Основано на:** [SPEC_PLAN/Narrative.md](Narrative.md), [требования v2](../docs/brainstorms/2026-08-04-tutu-swipe-discovery-requirements.md)

Каждый критерий приёмки имеет идентификатор `AC<N>`. Тесты обязаны называть критерий, который они фиксируют (принцип «тесты — это требования»).

---

## US1. Сформулировать поездку словами

**Как** человек, который не знает, куда поехать,
**я хочу** описать поездку обычной фразой,
**чтобы** не заполнять форму из полей, значения которых я ещё не выбрал.

| ID | Критерий приёмки |
|---|---|
| AC1 | Фраза со всеми параметрами (откуда, состав, период, бюджет, настроение) превращается в структуру поиска без уточняющих вопросов |
| AC2 | Отсутствие города отправления блокирует поиск и вызывает отдельный уточняющий шаг |
| AC3 | Упоминание детей без возрастов блокирует поиск и вызывает отдельный уточняющий шаг |
| AC4 | Нечёткий период («в сентябре») сводится к конкретному окну выезда; повторный разбор той же фразы даёт то же окно |
| AC5 | Бюджет трактуется как сумма на всю группу и всю поездку; «до 60к» и «60000 рублей» дают одинаковый результат |
| AC6 | Нераспознаваемый ввод получает осмысленный отказ с подсказкой, а не пустую структуру |

## US2. Увидеть варианты быстро

**Как** пользователь с телефона,
**я хочу** увидеть первые варианты почти сразу,
**чтобы** не смотреть на спиннер, пока система обходит десяток городов.

| ID | Критерий приёмки |
|---|---|
| AC7 | Для направлений каталога первая карточка появляется не позже 1,5 секунды от отправки запроса (p95 из десяти прогонов на production, холодная функция) — за счёт предзаготовленного снапшота |
| AC7a | Карточки снапшота заменяются живыми данными по мере ответа MCP; замена видна пользователю |
| AC7b | Для направления вне каталога живой поиск сопровождается индикатором с указанием, что ищется новое направление. Индикатор не засчитывается как выполнение AC7 |
| AC8 | Карточки появляются по мере готовности направлений, а не одним пакетом после завершения поиска |
| AC9 | Отказ или таймаут части направлений не выносит экран: показываются успешные, остальные помечаются как не отвеченные |
| AC10 | Отсутствие предложений даёт состояние «ничего не нашли» с предложением смягчить запрос |
| AC10a | Полная недоступность MCP показывается как недоступность источника, а не как отсутствие предложений |
| AC11 | Обрыв потока восстанавливается с последнего полученного события, без дублей и потерь; обновление страницы восстанавливает журнал реакций, позицию и состояние ранжировщика |

## US3. Смотреть готовые поездки, а не разрозненные билеты

**Как** пользователь,
**я хочу** видеть дорогу и жильё одним пакетом с итоговой ценой,
**чтобы** не складывать стоимость поездки в уме.

| ID | Критерий приёмки |
|---|---|
| AC12 | Карточка содержит дорогу туда-обратно, жильё и итоговую цену с разбивкой по компонентам |
| AC13 | Цена жилья берётся как итог за весь период проживания и не умножается на число ночей |
| AC14 | Прилёт позже 22:00 или выезд раньше 8:00 помечается предупреждением на карточке |
| AC15 | Направление без предложений по жилью или дороге не показывается как поездка |
| AC16 | Рядом с ценой отображается её возраст; перед переходом на Туту показывается предупреждение, что цена могла измениться |
| AC17 | При неоднозначности названия города карточка несёт признак неоднозначности с указанием выбранного населённого пункта и области |

---

## US4. Влиять на выдачу реакциями

**Как** пользователь,
**я хочу** чтобы лента подстраивалась под мои лайки и отказы,
**чтобы** не пролистывать одно и то же.

| ID | Критерий приёмки |
|---|---|
| AC18 | Дизлайк сопровождается выбором причины: дорого / долго добираться / не тот город / не тот отель |
| AC19 | Причина «не тот город» убирает город из выдачи; две такие причины подряд запускают подбор новых направлений |
| AC20 | Причина «дорого» понижает медианную цену последующих карточек |
| AC21 | Среди любых пяти подряд идущих карточек не более двух относятся к одному городу |
| AC22 | Отмена последней реакции возвращает предыдущую карточку и откатывает состояние модели и позицию в ленте |
| AC23 | Повторное срабатывание одной и той же реакции засчитывается один раз |
| AC24 | Реакция доступна и свайпом, и нажатием |
| AC25 | При одинаковой начальной установке и одинаковой последовательности реакций лента воспроизводится идентично |

---

## US5. Понимать, почему мне это показали

**Как** пользователь,
**я хочу** видеть причину рекомендации,
**чтобы** доверять выдаче, а не считать её случайной.

| ID | Критерий приёмки |
|---|---|
| AC26 | Объяснение появляется только при достаточном числе подтверждающих реакций; при недостатке не показывается вовсе |
| AC27 | Объяснение ссылается только на признаки, присутствующие в данных карточки |
| AC28 | Объяснение стабильно между вызовами при неизменном состоянии сессии и не зависит от случайной составляющей ранжирования |
| AC29 | Противоречивые реакции по признаку не порождают объяснения по этому признаку |

---

## US6. Поделиться результатом

**Как** человек, который выбирает поездку не один,
**я хочу** отправить готовую подборку,
**чтобы** обсудить её там, где мы и так переписываемся.

| ID | Критерий приёмки |
|---|---|
| AC30 | Подборка доступна начиная с пятой реакции, изменяется до девятой и замораживается на десятой |
| AC31 | Подборка содержит не более трёх вариантов |
| AC32 | Ссылка открывается на другом устройстве без сессии и без cookies |
| AC33 | Испорченная или несовместимая по версии ссылка даёт осмысленную страницу, а не ошибку сервера |
| AC33a | Параметры поездки (даты, бюджет, состав, возрасты детей) не попадают в серверные логи и в заголовок перехода |
| AC33b | Исчезнувшее к моменту открытия предложение заменяется актуальным по тем же параметрам с явной пометкой о замене |

---

## US7. Перейти к покупке

**Как** пользователь, выбравший вариант,
**я хочу** попасть на Туту с уже заполненными параметрами,
**чтобы** не вводить всё заново.

| ID | Критерий приёмки |
|---|---|
| AC34 | Надпись на кнопке соответствует типу перехода, который вернул сервис: корзина, выбор мест или подборка на Туту |
| AC35 | Состав пассажиров передаётся полностью, и сумма на Туту соответствует показанной с точностью до изменения цен |
| AC36 | Предложение с раздельными билетами показывает своё примечание до перехода |
| AC37 | Переход открывается синхронно по нажатию и не блокируется браузером |
| AC38 | Ошибка, таймаут или устаревшая ссылка перехода дают сообщение и запасной переход на результаты поиска |

## Метрики успеха

| Метрика | Целевое значение | Как измеряется |
|---|---|---|
| Время до первой карточки (направления каталога) | ≤ 1,5 с (p95) | Десять прогонов на production, холодная функция |
| Время до замены живыми данными | ≤ 12 с | Те же прогоны |
| Эффект обучения | Понравившиеся карточки в среднем выше в выдаче, чем при статическом ранжировании по цене | Протокол воспроизведения на зафиксированном снимке пула, три реализации на одном входе |
| Полнота сценария | Проходится целиком | Запрос → реакции → подборка → открытие ссылки на другом устройстве → переход на Туту |
| Устойчивость развёрнутого приложения | Полный сценарий проходит у стороннего человека | Production URL с мобильного и десктопа, холодный старт |
| Воспроизводимость записи | Дубль с фиксированным seed повторяется | Демо-режим, повторный прогон даёт ту же ленту |

## Вне области

- Синхронный свайп с нескольких устройств
- Аккаунты, авторизация, история между сессиями
- Оплата и бронирование внутри продукта
- Обучение на исторических данных
- Мобильное приложение
- Брендированные подборки под маркетинговые спецпроекты — упоминаются на защите как продолжение, не реализуются
- Голосовое управление фильтрами

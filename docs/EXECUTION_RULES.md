# Правила исполнения

Детали, вынесенные из `AGENTS.md`, чтобы тот остался картой, а не сводом. Здесь — как устроена работа: список фич, уровни приёмки, ревью, дисциплина фаз.

---

## Список фич — источник истины о том, что делать

Файл: `docs/features.json`. Каждая запись — тройка: поведение, команда верификации, состояние (`not_started` → `active` → `passing`, при провале `blocked`).

```bash
npm run features next          # какую фичу брать следующей
npm run features start F02     # взять в работу
npm run features verify F02    # запустить верификацию и обновить состояние
npm run features review F02 approved qwen "что проверено, что найдено"
```

1. **Состояния меняет только скрипт.** Руками `state` не правится — статус выставляется по коду возврата команды верификации.
2. **Одна активная фича за раз.** Нельзя начать вторую, не доведя первую.
3. **`passing` необратимо.** Изменилось поведение — заводится новая фича.
4. **`npm run check` перепроверяет все `passing`.** Статус, выставленный без реального прохождения, ловится здесь и в CI.
5. **Гранулярность — одна сессия.** «Пользователь может отменить последнюю реакцию» — верно. «Сделать рекомендации» — слишком широко.

Каждая фича ссылается на критерий приёмки из `SPEC_PLAN/PRD.md`. Фича без критерия — повод остановиться и спросить, зачем она.

## Уровни приёмки

| Уровень | Что | Команда | Когда обязателен |
|---|---|---|---|
| 1 | Типы, линт, границы | `npm run check` | всегда |
| 2 | Юнит- и интеграционные тесты | `npm run check` | всегда |
| 3 | Сборка, запуск, критические маршруты | `npm run smoke` | при изменениях на стыке компонентов |
| 4 | Ревью отдельным агентом | `npm run features review` | перед `passing` |

Не переходи к уровню 2, не пройдя уровень 1. Ненулевой код возврата — FAIL, дальше идти нельзя. Пропущенный обязательный уровень означает «не завершено», независимо от того, как выглядит код.

## Кто что делает

| Роль | Исполнитель | Чего не делает |
|---|---|---|
| Оркестрация, декомпозиция, артефакты | Claude | Не пишет код фаз |
| Реализация фазы | Codex CLI | Не выносит вердикт по своей работе |
| Ревью уровня 4 | Qwen 3 Max или отдельный агент | Не правит код, а описывает найденное |

**Ревью выносит не тот, кто писал.** У исполнителя издержки утопленных затрат и память «я уже решил, что тут нормально».

**Ограничение по ревьюеру:** Qwen отдаётся маленькими порциями — короткий промпт и небольшой файл за раз, иначе модель зависает. Большой дифф режется на куски и скармливается последовательно.

### Контракт вывода ревьюера

«Выглядит хорошо» не принимается. Вердикт по каждому измерению:

| Измерение | A | B | C | D |
|---|---|---|---|---|
| Корректность | все проверки зелёные | основной поток работает | частично | сборка падает |
| Соответствие замыслу | делает ровно заявленное | мелкие расхождения | заметные расхождения | делает не то |
| Архитектура | границы соблюдены | мелкие отклонения | явные отклонения | грубые нарушения |
| Тесты | основной путь и края | только основной путь | каркас | нет |

Любое `C` и ниже → `rejected` с указанием, что именно чинить.

## Дисциплина фаз

Исполняется только активная фаза из `SPEC_PLAN/phase-registry.md`.

- Не брать задачи из будущих фаз.
- Не менять файлы вне области фазы, кроме блокирующего исправления внутри текущей — и тогда это записывается в `HANDOFF.md`.
- Нужное, но принадлежащее будущей фазе, записывается как `Отложено в фазу N: причина` и попадает в `docs/tech-debt-tracker.md`.
- Ревью смотрит дифф текущей фазы против её определения готовности и затронутых критериев приёмки, а не против всего продукта.

## Что писать в документы

`docs/surprises.md` — только то, что нельзя вывести из общих знаний: странное поведение MCP, обходные пути, опасные места, неочевидные ограничения платформы. Проверка для каждой записи: **что сломается в следующей сессии, если этого не знать?**

Не документировать, что такое Next.js или Redis.

`docs/tech-debt-tracker.md` — всё отложенное. Отслеживаемый долг допустим, скрытый — нет.

## Чеклист выхода из сессии

- [ ] `npm run check` зелёный
- [ ] `npm run smoke` зелёный, если менялось на стыке компонентов
- [ ] Список фич отражает реальность (`npm run features list`)
- [ ] `PROGRESS.md` и `HANDOFF.md` обновлены
- [ ] Отложенное записано в `docs/tech-debt-tracker.md`
- [ ] Неочевидное записано в `docs/surprises.md`
- [ ] Порты свободны, временные файлы убраны

## Продвижение обратной связи в правила

Повторяющаяся ошибка, найденная на ревью, превращается в правило в `scripts/check-boundaries.mjs` с сообщением WHAT / WHY / FIX. Второй раз ту же ошибку ловит машина, а не человек.

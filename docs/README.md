# docs/

Рабочие документы проекта. Карта всего репозитория — `PROJECT_INDEX.md`, вход для агента — `AGENTS.md`.

| Файл | Когда открывать | Кто пишет |
|---|---|---|
| `EXECUTION_RULES.md` | Перед первой работой в проекте: фичи, уровни приёмки, ревью, дисциплина фаз | Обновляется при смене процесса |
| `features.json` | Каждую сессию: что делать дальше и что уже проверено | Только `scripts/features.mjs` |
| `surprises.md` | Когда внешняя система повела себя не так, как ожидалось | Исполнитель, в тот же день |
| `tech-debt-tracker.md` | Когда что-то откладывается | Исполнитель, в момент отклада |
| `QUALITY_SCORE.md` | После прохождения гейтов фазы | Исполнитель |
| `ranking-baseline.md` | Фаза 3: сравнение реализаций ранжировщика | Появится при выполнении U14 |
| `brainstorms/` | Первоисточник требований | Заморожено, правится только через новую ревизию |
| `plans/` | Технический план с юнитами U1–U14 | Заморожено, правится только через новую ревизию |
| `architecture/`, `product/`, `delivery/`, `decisions/` | Разрастание соответствующих разделов | По мере необходимости |
| `archive/` | Вытесненные детали, которые жалко удалить | При реструктуризации |

## Что сюда писать, а что нет

Пиши только то, что нельзя вывести из общих знаний: странности внешних систем, обходные пути, опасные места, неочевидные ограничения платформы.

Проверка для каждой записи: **что сломается в следующей сессии, если этого не знать?** Если ответ «ничего» — запись не нужна.

Не описывай, что такое Next.js, Redis или MCP. Описывай, чем конкретно MCP Туту отличается от ожидаемого.
